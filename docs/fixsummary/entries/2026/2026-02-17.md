# LineageOS 23 (m2391) 构建冲突修复总结

日期: 2026-02-17  
范围: `device/meizu/m2391`, `vendor/meizu/m2391`（通过重新生成）  
目标: 解决 `kati` 阶段大量 `overriding commands for target` 冲突，恢复 `mka recoveryimage` 构建链路。

## 1. 问题现象

在执行 `mka recoveryimage` 时，`kati` 报错类似：

- `overriding commands for target out/target/product/m2391/vendor/bin/audioadsprpcd`
- `overriding commands for target out/target/product/m2391/vendor/bin/boringssl_self_test64`
- `overriding commands for target out/target/product/m2391/vendor/bin/checkpoint_gc`
- `overriding commands for target out/target/product/m2391/vendor/bin/cplay`
- `overriding commands for target out/target/product/m2391/vendor/etc/IPACM_Filter_cfg.xml`
- `overriding commands for target out/target/product/m2391/vendor/lib64/camera.device@1.0-impl.so`

## 2. 根因分析

根因是**同一路径被定义了两次安装规则**：

1. 一份来自 `device/meizu/m2391/proprietary-files.txt` 的 blob 拷贝规则（`MAKE_COPY_RULE_ONLY`），最终生成到 `vendor/meizu/m2391/m2391-vendor.mk`。  
2. 另一份来自 Soong/AOSP/QCOM 源码模块（`out/soong/installs-lineage_m2391.mk`）。

当两者都安装到同一个 `out/target/product/m2391/vendor/...` 目标路径时，`kati` 直接失败。

## 3. 修复策略

采用“两步法”：

1. 从 `device/meizu/m2391/proprietary-files.txt` 删除与 Soong 安装路径重叠的条目。  
2. 执行 `device/meizu/m2391/extract-files.py --regenerate_makefiles` 重新生成 `vendor/meizu/m2391/m2391-vendor.mk`，确保修复可持续（避免下次提取又回滚）。

为避免一条条报错反复处理，后续改为**按路径类别批量去重**（`vendor/bin`、`vendor/etc`、`vendor/lib64`）。

## 4. 已完成修复内容

### 4.1 单点先行修复

初期先移除了典型冲突项：

- `vendor/bin/audioadsprpcd`
- `vendor/bin/boringssl_self_test32`
- `vendor/bin/boringssl_self_test64`
- `vendor/etc/init/boringssl_self_test.rc`
- `vendor/bin/checkpoint_gc`

### 4.2 批量修复（vendor/bin）

一次性移除与 Soong 重叠的 `vendor/bin/*` 条目（共 18 项），包含：

- `vendor/bin/cplay`
- `vendor/bin/dumpsys`
- `vendor/bin/ipacm`
- `vendor/bin/nqnfcinfo`
- `vendor/bin/vendor.qti.qspa-service`
- `vendor/bin/wpa_cli`
- 及若干 `vendor/bin/hw/*` 服务项（例如 display/health/vibrator/wpa_supplicant 等）

### 4.3 批量修复（vendor/etc）

一次性移除与 Soong 重叠的 `vendor/etc/*` 条目（共 28 项），包含：

- `vendor/etc/IPACM_Filter_cfg.xml`
- `vendor/etc/IPACM_cfg.xml`
- 若干 `vendor/etc/init/*.rc`
- 若干 `vendor/etc/vintf/manifest/*.xml`
- `vendor/etc/wifi/wpa_supplicant.conf`
- 以及少量配置资源文件

### 4.4 批量修复（vendor/lib64）

一次性移除与 Soong 重叠的 `vendor/lib64/*` 条目（共 175 项），包含：

- `vendor/lib64/camera.device@1.0-impl.so`
- `vendor/lib64/camera.device@3.x-impl.so`
- 若干 `vendor/lib64/hw/*.so`
- 若干通用/多媒体/音频/显示相关库

说明：`vendor/lib` 本轮无重叠项，未做批量删除。

## 5. 当前结果

基于当前工作区（`out/soong/installs-lineage_m2391.mk`）复核结果：

- `vendor/bin overlaps: 0`
- `vendor/etc overlaps: 0`
- `vendor/lib overlaps: 0`
- `vendor/lib64 overlaps: 0`

即 `proprietary-files.txt` 与 Soong 目标安装路径在上述四类路径中已无重叠定义。

## 6. 后续建议

1. 重新执行完整构建验证：
   - `source build/envsetup.sh`
   - `lunch lineage_m2391-bp4a-userdebug`
   - `mka recoveryimage` / `mka bacon` / `brunch lineage_m2391-bp4a-userdebug`
2. 若出现新的 `overriding commands for target`，优先按**路径类别**批量扫描，而不是逐条修。
3. 保持当前“最小可启动 blob 策略”：
   - 让 AOSP/QCOM 源码模块优先提供可重建组件；
   - 仅保留无法由源码提供的专有项。
4. 后续在可启动后，再分阶段回补确实必须的专有库/配置，避免一次性引入大规模冲突。
