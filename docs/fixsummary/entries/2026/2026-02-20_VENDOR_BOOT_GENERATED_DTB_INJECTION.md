# LineageOS 23 (m2391) generated vendor_boot DTB injection fix

Date: 2026-02-20  
Scope: `device/meizu/m2391`  
Target: re-enable build-generated `vendor_boot.img` and fix missing DTB payload (`dtb size: 0`).

## 1. Symptom

When `vendor_boot.img` was generated by build rules, unpack comparison previously showed:

- `dtb size: 0`
- recovery boot was unstable / unable to enter on-device

The prebuilt stock `vendor_boot.img` did not show this issue (non-zero DTB).

## 2. Root cause

Generated `vendor_boot` path was active, but DTB input was not wired into fsgen boot image creation.
As a result, mkbootimg output for `vendor_boot` missed `--dtb`.

## 3. Fix

### 3.1 Re-enable generated vendor_boot path

In `device/meizu/m2391/BoardConfig.mk`:

- remove `BOARD_PREBUILT_VENDOR_BOOTIMAGE`
- keep prebuilt kernel `Image` input (`TARGET_PREBUILT_KERNEL`)

### 3.2 Force DTB inclusion into generated vendor_boot

In `device/meizu/m2391/BoardConfig.mk`:

- set `BOARD_INCLUDE_DTB_IN_BOOTIMG := true`

In `device/meizu/m2391/device.mk`:

- add:
  - `$(KERNEL_PATH)/dtb.img:dtb.img`

This feeds fsgen DTB discovery for vendor_boot generation and restores non-zero DTB content.

## 4. Validation checklist

1. `source build/envsetup.sh`
2. `lunch lineage_m2391-bp4a-userdebug`
3. `mka vendorbootimage recoveryimage`
4. unpack generated image and verify:
   - `out/target/product/m2391/vendor_boot.img` has non-zero `dtb size`
5. flash and verify:
   - device can enter recovery with generated `vendor_boot.img`
   - `adb devices` still works in recovery

## 5. Notes

- This change addresses the DTB omission path first.
- If recovery bring-up still fails after DTB injection, next step is aligning generated
  vendor ramdisk kernel module set and load lists with stock composition.
